# DAYMARK LIFE

研究（スポーツ科学・野球）と私生活の記録・可視化・振り返りのための個人用Webサイト。
ビルド不要の静的サイト（HTML/CSS/JavaScriptのみ・外部ライブラリなし）で、
どの静的ホスティングにも置けるほか、PCでフォルダを開いてローカルでも動く。

- データはすべて**この端末のブラウザ内（localStorage）にのみ保存**し、外部サーバーへは送信しない。
- アカウント登録・外部API・有料サービスは不要。AI添削・音声会話は**このサイトには無く**、
  ChatGPT等へのリンクとコピー用プロンプトで連携する。
- 日付は日本時間（Asia/Tokyo）で扱う。

## 画面と機能

| 画面 | 主な機能 |
|---|---|
| ホーム | 今日の日付・予定・タスク、研究/英語/運動の今日と今週、コンディション、今週の目標、直近2週間のグラフ、バックアップ催促 |
| 予定表 | 日（24時間の予定と実績を並べて表示、空き時間タップで追加）／週／月／タスク一覧。予定ごとに「実施した・一部・しなかった」と実際の時間を記録 |
| 英語 | 学習時間（技能・場面つき）、継続日数・累計・頻度、英語日記（お題・下書き自動保存・添削結果の貼り付け）、表現・単語帳、苦手リストと間隔反復の復習、ChatGPT音声会話用プロンプト（編集可） |
| 研究 | プロジェクト（目標・期限・進捗）、研究タスク（期限・優先度・種類）、研究時間（今日/今週/今月）、作業の内訳、成果メモ、週の振り返り |
| コンディション | 7項目の0〜100スライダー（未入力を区別）、就寝・起床から睡眠時間を計算、推移グラフ、一覧 |
| 運動 | 種目・時間・RPE（CR-10）、週/月の回数、累計時間、12週の実施カレンダー、セッションRPE負荷 |
| 分析 | 記録率、カテゴリー別内訳、研究/英語/運動の推移、睡眠と疲労、項目別推移、予定と実績、目標達成率、2変数の散布図（探索） |
| 目標・習慣 | 週間/月間目標（手動 or 記録から自動判定）、習慣チェック表、休息日・自由時間、週の振り返り |
| 設定・データ | JSON書き出し/読み込み、CSV書き出し、自動控え（直近3日）からの復元、カテゴリー・選択肢・習慣の編集、表示テーマ |

画面下（スマホ）の「＋」から、どの画面にいても時間・コンディション・予定・タスク・振り返り・英語表現を記録できる。
削除した直後は「元に戻す」が出る。

## 公開方法（普通のHTTPS URLで使う）

このフォルダ（`daymark-life/`）をそのまま静的ホスティングに置けばよい。ビルドコマンドは不要。

**推奨：Cloudflare Pages または Netlify を GitHub リポジトリに接続する**（リポジトリを非公開のまま公開できる）

1. Cloudflare Pages（または Netlify）に GitHub アカウントでログインし、このリポジトリを選ぶ。
2. 設定：ビルドコマンド＝なし（空欄）、ルート／ベースディレクトリ＝`daymark-life`、出力ディレクトリ＝`daymark-life`（ベースからの相対なら `.`）。
3. デプロイすると `https://〜.pages.dev`（Netlifyなら `https://〜.netlify.app`）のURLが発行される。
4. 以後、`main` ブランチに変更が入るたびに自動で再公開される。

**別案：GitHub Pages** — 無料プランでは公開リポジトリが必要。コードだけを別の公開リポジトリに置き、
Settings → Pages → 「Deploy from a branch」で公開する（記録データはリポジトリに含まれないので、コードを公開しても個人データは公開されない）。

### iPhoneでの使い方（重要）

1. SafariでURLを開き、「共有」→「ホーム画面に追加」。以後はホーム画面のアイコンから起動する。
2. **週に1回程度「設定・データ」→「データを書き出す」**でバックアップし、iCloud Drive等にも置いておく。

理由：WebKit（Safari）は、ホーム画面に追加していないサイトについて、ユーザーが7日間そのサイトを操作しないと
スクリプトが書き込んだ保存データ（localStorage等）を削除する仕様を導入している。ホーム画面に追加したWebアプリは
この対象外とされている（WebKit公式ブログ "Full Third-Party Cookie Blocking and More", 2020年3月24日,
https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ ）。
ただし端末の故障・機種変更・ブラウザのデータ消去では消えるため、書き出しによるバックアップは必須。

端末間の自動同期はない（サーバーを持たない設計のため）。端末を移るときは書き出し→読み込みを使う。

## 変更・修正のしくみ

### 使いながら変えられること（コード不要）
- カテゴリー名の変更・追加（最大8つ）、研究の作業の種類・英語の技能/場面・運動の種目の追加/改名/並べ替え/削除、生活習慣の追加/停止
- 英語の練習用プロンプトの追加・編集・削除、ChatGPTのリンク先
- ホームの1週間の目安（研究時間・英語時間・運動回数）、目標（週間/月間、判定方法）
- すべての記録の編集・削除（削除直後は元に戻せる）、自動控えからの復元、直前の読み込みの取り消し

### コードを改修するとき（Claude Code 等に依頼する場合も同じ）
1. 変更は小さく分けて行い、`node tests/e2e.js` を実行して**すべての確認に成功**することを確かめる
   （iPhone相当の画面で全ページを操作し、追加・編集・削除・元に戻す・再読み込み後の保持・書き出し/読み込みを検証する。要 Playwright）。
2. **保存データの形を変えるとき**は `js/store.js` の `SCHEMA` を1つ上げ、`MIGRATIONS` に古い形からの変換を書く。
   既存の記録は読み込み時に自動変換される。項目を「足すだけ」なら `emptyData()`／`DEFAULT_SETTINGS` に既定値を足せば
   `normalize()` が古いデータを補完する。
3. ファイルを追加・改名したら `index.html` の `<script>` と `sw.js` の `ASSETS` を更新し、`sw.js` の `CACHE` と
   `js/store.js` の `APP_VERSION` を上げ、`CHANGELOG.md` に追記する。
4. `main` に反映すると、接続したホスティングが自動で再公開する。Service Worker はネットワーク優先なので、
   オンラインで開けば新しい版が読み込まれる（「設定・データ」→「更新を確認」でも可）。

### ファイル構成
```
index.html            画面の土台（スクリプトの読み込み順に意味がある）
css/app.css           見た目（色はすべて先頭の変数。ダークモードも同じ場所）
js/util.js            日付（日本時間）・書式・統計の小道具
js/store.js           保存・スキーマ移行・書き出し/読み込み・自動控え
js/model.js           集計（記録のない日を0にしない）、コンディション項目の定義、目標判定
js/charts.js          SVGグラフ（折れ線・積み上げ棒・散布図・割合・実施カレンダー）
js/ui.js              シート・フォーム部品（VASスライダー等）・トースト・確認
js/forms.js           各記録の入力フォーム（時間・予定・タスク・コンディション・振り返り・プロジェクト・目標・表現）
js/views/*.js         各画面
js/app.js             画面切り替え（#/画面名?パラメータ）・ナビゲーション・起動
sw.js                 オフライン対応
tests/e2e.js          動作確認テスト
tools/build-standalone.js  1ファイル版（dist/daymark-life.html）を作る
```

## 設計上の判断と根拠

事実（文献に書かれていること）と、このアプリでの判断を分けて記す。

- **コンディションの0〜100スライダー**：Visual Analogue Scale の形式を借りた**単一項目の主観評価**。
  このアプリの各項目・アンカー文言について信頼性・妥当性を検証した研究はない（＝独自の記録用尺度）。
  個人内の推移を見る目的に限定し、診断・健康判定は行わない。未操作の項目は「未入力」として保存しない（判断）。
- **RPE（CR-10）とセッションRPE負荷**：Foster C, et al. (2001) "A new approach to monitoring exercise training."
  *J Strength Cond Res* 15(1):109–115. セッション終了の約30分後にCR-10でRPEを評価し、時間（分）を掛けた値を
  負荷として用いる方法。異なる種目間で負荷の意味が同じとは限らないため、画面上で注意書きを出す（判断）。
- **記録のない日の扱い**：記録がない日は「0」ではなく欠測とし、グラフでは線をつながない。
  期間平均は記録のある日だけで計算する（判断）。分析の散布図では、時間系の変数は「その日に何らかの記録がある日」
  に限り未記録カテゴリーを0分とみなす（判断：記録した日に記載がなければ実施していない可能性が高いと仮定）。
- **2変数の関係（散布図）**：Spearmanの順位相関を、両方の値がそろった組が**14組以上**のときだけ表示する。
  14という数は統計的に導いた値ではなく、「2週間分程度はそろってから眺める」という**研究デザイン上の判断**である。
  同一個人の連続した日の記録は独立ではなく（自己相関）、共通要因の影響も受けるため、p値は出さず、因果の解釈もしない。
- **研究の「成果につながったか」**：記録時間のうち「成果メモ」を書いた時間の割合と、完了タスク数を並べて示す。
  成果の質の指標ではなく、振り返りのきっかけとしての表示である（判断）。
- **フレーズ復習の間隔**（1→3→7→14→30→60日）：ライトナー方式の考え方に沿った**固定の間隔（判断）**で、
  最適な間隔として検証されたものではない。
- **配色**：カテゴリー5色は、隣り合う色が色覚特性のシミュレーション上でも区別できること（OKLab色差）を
  検証スクリプトで確認した順序付きパレットを使用。ライトモードでは一部の色が背景とのコントラスト3:1未満のため、
  凡例・表・文字ラベルを必ず併記し、色だけで区別させない（判断）。

## 動作環境
iOS 16.4 以降の Safari、最近の Chrome / Edge / Firefox を想定（CSSの `color-mix()` 等を使用）。
